# 需求挖掘案例：某 SaaS 企业客服智能化

> **DEV-001** | M0 设计评审材料 | 日期：2026-06-01

---

## 1. 客户原话

> 「我们想搞点 AI，提升客服效率，领导让 Q3 前出个方案。」

**背景**：某 B2B SaaS 公司（500 人规模），客服团队 35 人，日工单量 800+，服务 2000+ 企业客户。

---

## 2. 干系人地图

| 角色 | 人物 | 关注点 | 决策权 |
|------|------|--------|--------|
| 业务高管 | 张 VP（运营副总） | ROI、客户满意度 NPS | ★★★ 最终拍板 |
| 客服主管 | 李经理 | 人均产能、培训成本 | ★★☆ 方案验收 |
| 一线客服 | 20 名坐席 | 重复劳动、系统难用 | ★☆☆ 共创反馈 |
| IT 负责人 | 王工 | 系统集成、数据安全 | ★★☆ 技术否决权 |
| 采购 | 赵姐 | 预算 ≤ 80 万/年 | ★★☆ 合同签署 |

**决策链**：张 VP ← 李经理 + 王工联合推荐 ← 我们的方案

---

## 3. 五 Whys 挖掘

| 层级 | 问题 | 回答 |
|------|------|------|
| Why 1 | 为什么要搞 AI？ | 客服成本占运营成本 18%，CEO 要求降 15% |
| Why 2 | 为什么成本高？ | 60% 工单是重复性问题（FAQ 可覆盖） |
| Why 3 | 为什么重复问题还进人工？ | 知识库检索命中率 < 55%，坐席宁可问同事 |
| Why 4 | 为什么检索命中率低？ | 知识库 2000+ 篇文档，无智能检索；且老用户每次重复描述问题 |
| Why 5 | 根本原因？ | **缺 Agent 能力边界（Skill 不清）+ 无跨会话 Memory + 无效果度量体系** |

---

## 4. 真实痛点（量化）

| # | 痛点 | 现状数据 | 业务影响 |
|---|------|----------|----------|
| P1 | 工单重复录入 | 占坐席工时 **40%** | 人均日处理 28 单（目标 40） |
| P2 | 知识检索失效 | 命中率 **< 55%** | FAQ 类工单本可自助 |
| P3 | 老用户重复描述 | 重复描述率 **32%** | NPS 下降 8 分 |
| P4 | Agent 行为不可预测 | 试点聊天 Demo 解决率 **< 45%** | 李经理拒绝上线 |
| P5 | 无法归因优化 | 无 Bad Case 体系 | 迭代靠猜 |

---

## 5. 隐性约束

| 约束 | 来源 | 影响 |
|------|------|------|
| 数据不出境 | 王工 / 合规 | 必须私有化部署或国内云 |
| 工单系统不可替换 | 已用 5 年自研工单 | 必须 API 嵌入，不能换系统 |
| 退款/状态变更不能交给 LLM | 财务合规 | 规则引擎兜底 |
| Q3 前上线 MVP | 张 VP | 12 周 → **本周出可演示原型** |
| 预算 80 万/年 | 采购 | 不含大规模 GPU 集群 |

---

## 6. Trade-off 工作坊结论

| 选项 | 优点 | 缺点 | 决策 |
|------|------|------|------|
| A. 全 LLM 客服 | 灵活 | 2B 不可控，合规风险 | ❌ 否决 |
| B. 纯 FAQ 机器人 | 确定性高 | 无法处理工单/升级 | ❌ 范围太窄 |
| C. **Skill + Harness + Memory 混合 Agent** | 边界清晰、可评测、可嵌入 | 设计复杂度高 | ✅ **选定** |
| D. 先做销售 Agent | 销售 VP 推动 | ROI 低于客服（数据支撑） | ❌ 二期 |

**MVP 范围**：

- ✅ 智能客服 Agent（咨询 + 工单 + 升级）
- ✅ 嵌入现有工单系统 + 知识库
- ✅ Skill 边界 + Harness 确定性 + Memory 跨会话
- ❌ 销售 Agent、风控 Agent（二期）

---

## 7. 方案边界与成功指标

| 指标 | 基线 | MVP 目标（30 天） | 度量方式 |
|------|------|------------------|----------|
| 一次解决率 | 45% | ≥ 75% | Eval Harness |
| 人均日处理工单 | 28 | ≥ 35 | 工单系统统计 |
| 重复描述率 | 32% | ≤ 10% | Episodic Memory 效果 |
| 知识检索命中率 | 55% | ≥ 80% | RAG 评测集 |
| 转人工率 | — | ≤ 15% | Agent 运营面板 |

## 8. 客户沟通记录摘要

**第一次会议（Discovery）**：

- 张 VP：「不要 PPT，要跑得起来的 Demo。」
- 李经理：「上次供应商的聊天机器人连工单号都 hallucinate，不会再踩坑。」
- 王工：「API 文档我可以提供，但数据不能出 VPC。」

**第二次会议（Trade-off 工作坊，2h）**：

- 共同确认：先做客服 Agent，拆成 12 个 Skill，每个 Skill 可独立评测
- 王工接受：Harness Guardrail + 规则引擎兜底退款/状态变更
- 李经理要求：跨会话 Memory，「客户不想每次重复说订单号」
