# UAT 与用户验收计划

> **文档编号** DOC-AOPS-UAT-001 · **版本** v1.0  
> **项目**：智服通 AgentOps MVP  
> **客户**：某 SaaS 企业客服团队

---

## 1. 验收目标

在 **staging 环境** 完成用户验收测试（UAT），证明系统满足 [PRD §15](./02-PRD-智服通AgentOps.md) 业务指标与 [RTM](./16-fr-traceability-matrix.md) 全部 P0 需求，达到 **试运行** 准入条件。

---

| 角色 | 人员 | 职责 |
|------|------|------|
| 验收负责人 | 李经理 | 组织 UAT、确认业务场景 |
| IT 验收 | 王工 | API 联调、安全、部署确认 |

## 4. UAT 测试用例

### 4.1 业务场景（必测 · 7 条）

| ID | 场景 | 操作步骤 | 预期结果 | 关联 FR |
|----|------|----------|----------|---------|
| **UAT-01** | 知识咨询 | 输入「企业版和专业版区别」 | 回答含套餐差异 + 知识库引用链接 | F-010,011 |
| **UAT-02** | 报修建单 | 输入「服务器宕机，请尽快处理」 | 返回工单号；工单系统可查 status=new | F-020 |
| **UAT-03** | 查进度 | 输入「查 T-xxx 进度」（不创建新单） | 返回状态；工单系统无重复新建 | F-022 |
| **UAT-04** | 跨会话 | Session1 建单 → 关闭 → Session2 问进度 | 准确引用历史工单，不要求重复描述 | F-051 |
| **UAT-05** | 投诉升级 | 输入激烈投诉「三次没解决」 | 转人工队列有记录；话术合规 | F-030~032 |
| **UAT-06** | 敏感拦截 | 输入含手机号/密码 | Guardrail 拦截，不进 LLM | F-040 |
| **UAT-07** | 字段追问 | 输入「我要报修」（无详情） | 模板追问 title/优先级，不 hallucinate 工单 | F-021 |

### 4.2 IT 场景（必测 · 3 条）

| ID | 场景 | 预期 | 关联 |
|----|------|------|------|
| **UAT-IT-01** | JWT 认证 | 无 Token 401；有效 Token 200 | API 规格 §1 |
| **UAT-IT-02** | Trace API | GET /traces/{id} 返回完整 steps | F-061 |
| **UAT-IT-03** | 限流 | 超 60 req/min 返回 429 | API 规格 §6 |

### 4.3 运营场景（选测 · 3 条）

| ID | 场景 | 预期 |
|----|------|------|
| UAT-OPS-01 | Skill 健康度面板 | 各 Skill 有成功率 |
| UAT-OPS-02 | Eval 报告 | 可下载 HTML/JSON |
| UAT-OPS-03 | Bad Case 标记 | 可归因到 Skill 层 |

## 5. 业务指标验收（30 天试运行后）

| 指标 | 基线 | 目标 | 度量方式 | 数据源 |
|------|------|------|----------|--------|
| 一次解决率 | 45% | ≥75% | 抽样 200 会话 | Agent + 工单 |
| 人均日处理 | 28 | ≥35 | 工单系统报表 | 客户 BI |
| 重复描述率 | 32% | ≤10% | 会话分析 | Trace |
| 转人工率 | — | ≤15% | 升级队列 / 总会话 | 运营后台 |
| 客户满意度 | — | ≥4.0/5 | UAT 后问卷 | 坐席反馈 |

## 6. 缺陷分级与退出准则

### 6.1 缺陷等级

| 级别 | 定义 | 处理时限 |
|------|------|----------|
| P0 | 阻塞 UAT、数据丢失、安全漏洞 | 24h 内修复 |
| P1 | 核心场景失败、错误建单 | 3 工作日 |
| P2 | 体验问题、非核心路径 | 试运行期间 |
| P3 | 优化建议 |  backlog |

### 6.2 UAT 通过准则

- [ ] §4.1 全部 7 条 **Pass**
- [ ] §4.2 全部 3 条 **Pass**
- [ ] **无 P0 开放缺陷**
- [ ] **P1 ≤2 且均有 workaround**
- [ ] Eval 120 条 staging ≥85%
- [ ] 王工 IT 安全审查签字
- [ ] 李经理业务签字

### 6.3 不通过处理

1. 供应商 3 个工作日内提交修复计划  
2. 回归 UAT 仅测失败项 + 关联 RTM  
3. 第三次 UAT 仍不通过 → 升级张 VP 决策
